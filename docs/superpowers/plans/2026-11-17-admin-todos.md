# 管理后台待办与邮件提醒

**目标：** 管理员维护自己的待办，在指定时间收到一次邮件提醒。

**实现：** MySQL 保存待办和提醒状态；Celery beat 每 60 秒投递检查任务，worker 复用进程生命周期中的数据库连接。通过数据库条件更新领取提醒，使用版本和租约处理并发、编辑和进程中断。邮件使用腾讯企业邮箱兼容的 SMTP SSL，也支持 STARTTLS。

- [x] 邮件与任务：新增通用 SMTP 发送器、每分钟到期检查、发送状态、最多三次尝试及过期租约恢复。测试重复检查、服务重启后的补发、失败退避、取消和发送成功后的去重。
- [x] 管理界面：新增“待办事项”菜单、筛选列表及编辑弹窗，提醒时间按浏览器本地时区输入并传带时区的 ISO 时间；显示接收邮箱和发送结果。

- [x] 集成验证：后端 260 项通过、21 项因未配置独立 Redis 集成测试地址跳过；前端测试及生产构建通过，Compose 配置校验通过。独立复核确认时区处理和私人待办日志脱敏正确。实际邮件联调需填写 SMTP 账号与密码。

## 行为约定

- 单次提醒，允许保存无截止时间或关闭提醒的待办；启用提醒必须有截止时间。
- 待办按管理员隔离；每条待办在管理后台单独保存收件邮箱，不使用环境变量统一覆盖。
- 完成待办会关闭提醒，重新打开待办不会自动重新开启提醒。修改已发送事项的标题、内容不会重复发送；修改时间或重新启用提醒则重新安排。
- 到期检查通常有一分钟以内的调度延迟；服务停机后恢复时补发仍未完成的到期提醒。
- 失败最多尝试三次，分别在一分钟和五分钟后重试；达到上限后可在列表中手动重试。未配置邮件时保留待发送事项，不消耗尝试次数。
- SMTP 不提供事务发送；服务器已接受邮件而进程在保存结果前中断时，租约恢复可能造成重复邮件。
